Akademiya 부속 서비스 PyDe Web을 제작하려고 해
### 중요한 원칙

기존 코드와 동일한 기능을 새로 구현하지 않는다.

기존 코드에 재사용 가능한 컴포넌트, 유틸리티, API, 인증 로직, CSS 등이 있다면 최대한 재사용한다.

"비슷하게 새로 만드는 것"보다 "기존 구현을 찾아 재사용하는 것"을 우선한다.

기존 구현을 그대로 사용할 수 없는 경우에만 PyDe Web에 맞게 확장하거나 새로 구현한다.

1. 프로젝트 개요/기존 서비스와의 연동성
  1-1. Pyodide 기반 교육용 Web Python IDE이다.
  1-2. 코드베이스의 GMCAuto 3처럼 독립 웹 앱으로 만든다. 기술 스택은 GMCAuto 3과 일치시킨다. Node.js, React, Vite, Express.js 등의 버전 역시 GMCAuto 3과 일치시킨다.
  1-3. IDE 기반으로는 Monaco Editor을 사용한다. 다만 Akademiya CSS의 테마 배색을 사용한다. 코딩툴이므로 다크 모드 전용으로 한다.
  1-4. Akademiya 계정으로 로그인할 경우 자동 저장으로 5분마다 서버에 저장한다. 해당 계정의 Akademiya Cloud 내부 'PyDe Web' 폴더에 저장한다. (Akademiya Cloud는 추후 보이는 서비스로 확장 가능하지만 현재는 내부적으로만 사용하게 하며, PyDe Web과 관련 없는 순수 클라우드 관련은 Akademiya 개인정보 처리방침과 이용 약관에 반영한다.) 계정 단위로 접근 권한을 보호하되, 공유 버튼을 누르면 Google Colab처럼 공유 범위(직접 이메일 입력/조직 단위 전원/링크(URL) 공개)를 정하여 공유 가능하게 - Akademiya surveys 코드 참고.
  1-5. 로그인이 필수여서는 안 된다. 하지만 로그인 기능을 넣어서 클라우드 사용 이권을 보장한다. Akademiya OpenOAuth 방식으로 진행하며, 작업 후 push하기 전에 나에게 요청해서, 내가 정부 양식 PDF 파일을 주면 개인정보 처리방침과 이용 약관을 작성한다.
  1-6. 중복 코드를 최대한 작성하지 않고 기존 코드의 재사용이 가능하면 최대한 재사용한다.
2. 사용 가능한 코드 범위
  2-1. Python 프로그래밍 언어에 한정하며, 브라우저 Pyodide를 이용하여 구동시켜 서버의 부담을 최소화한다.
  2-2. .py 파일과 .ipynb (Jupyter Notebook) 파일을 모두 지원한다.
  2-3. NumPy, Pandas, Matplotlib, SciPy, Scikit-learn 사용이 가능하게 한다.
  2-4. 코드의 실행 결과는 터미널 형태로 하단에서 보이도록 한다.
  2-5. 이미지 파일, 그래프 등이 생성되는 경우 하단 우측에 캔버스로 결과를 띄운다.
  2-6. 가능하면 Python 실행 환경을 Web Worker에서 구동하여 IDE UI가 무거운 Python 작업으로 인해 멈추지 않도록 설계한다.
[에디터 상세 사항]
`.py`는 일반적인 Python 소스 파일처럼 편집하고 실행한다.

`.ipynb`는 Jupyter Notebook의 기본 구조를 유지하면서 셀 단위로 편집 및 실행할 수 있도록 한다.

Notebook의 경우 가능한 한 Jupyter Notebook 사용자에게 익숙한 UX를 제공한다.

3. 보안
  3-1. Python 코드는 그 어떠한 경우에도 서버에서 실행되어서는 안 된다. 오로지 브라우저 샌드박스 안에서만 Pyodide를 이용하여 실행한다.
  3-2. 파일 권한: 기본적으로 파일은 해당 Akademiya 계정에 귀속된다. 사용자는 자신의 파일에 대해서만 기본적으로 접근할 수 있어야 한다. 서버 API에서 반드시 사용자 인증 및 권한 검사를 수행한다. 단순히 클라이언트에서 user ID를 보내는 것만으로 다른 사용자의 파일에 접근할 수 있는 구조를 만들지 않는다. IDOR 등의 권한 우회가 발생하지 않도록 한다.
  3-3. 파일 공유: 파일에는 "공유" 기능을 제공한다. 공유 권한 및 API 구현은 반드시 기존 Akademiya surveys의 공유 기능을 먼저 분석한다. 이미 구현된 사용자/조직/권한 모델이 있다면 최대한 재사용한다.

[보안 상세 사항]
Python은 반드시 Pyodide를 사용한다.

절대로 다음과 같은 방식으로 Python을 서버에서 실행하지 않는다.

- Python subprocess
- child_process
- exec
- spawn
- 서버 Python 런타임
- 서버에서의 eval/exec
- Python 실행을 위한 별도 서버
- 서버에서 사용자의 Python 코드를 직접 실행하는 API

사용자의 Python 코드는 오직 브라우저의 Pyodide에서 실행되어야 한다.

서버는 Python 코드 실행 결과를 계산하지 않는다.

4. 디자인
  4-1. 기본적으로 Akademiya의 다크 모드와 같은 배색을 사용한다.
  4-2. 다만 코드 에디터 부분의 텍스트 컬러는 Monaco Editor의 것을 사용한다.
  4-3. 첫 실행 시 파이썬의 파란색과 노란색, 그리고 사이 Akademiya의 밝은 초록색이 부드럽게 움직이면서 섞이는 그라데이션 애니메이션을 보여주면서 (Windows 11 OOBE처럼), 하단에 로딩 바와 진행도를 띄우고 로딩 바 바로 위에는 현재 무엇이 다운로드 중이고, 무엇을 준비하고 있는지 언어에 맞춰서 표시하며, 자세히 보기 버튼을 누르면 약간 확장되어 열리면서 실제 Pyodide 터미널 로그가 주르륵 표시되도록 한다. 이때 모든 라이브러리를 최초 접속 때 사전 로딩하여 실제 코드 실행시에 최대한 빠르게 실행되도록 한다. 그 후 재실행 시에는 라이브러리 버전만 체크한 후, 같다면 브라우저 캐시를 사용한다. 실제 다운로드/초기화 상태와 일치하지 않는 가짜 진행률을 보여주지 않는다. 가능하면 실제 다운로드 진행 상황을 기반으로 진행률을 계산한다. 정확한 진행률을 알 수 없는 단계는 indeterminate progress 상태를 사용한다. 자세히 보기에서는 가능하면 실제 Pyodide 로딩 상태를 기반으로 로그를 생성한다. 단순히 미리 만들어 둔 가짜 로그를 빠르게 출력하는 방식은 사용하지 않는다.

  5-2. Python traceback도 가능한 한 사용자에게 읽기 쉬운 형태로 표시한다.

6. Cloud 주의 사항

로그인한 사용자의 작업물은 해당 계정의 Akademiya Cloud 내부에 저장한다.

기본 저장 경로:

Akademiya Cloud/
└── PyDe Web/
    ├── example.py
    ├── exercise.py
    └── notebook.ipynb

현재 Akademiya Cloud 자체를 별도의 공개 서비스 UI로 확장할 필요는 없다.

PyDe Web에서 내부적으로 Cloud 저장소를 사용하는 형태로 구현한다.

다만 향후 Akademiya Cloud를 독립적인 서비스로 확장할 가능성을 고려하여 API와 데이터 구조를 지나치게 PyDe Web에 종속시키지 않는다.
